# Changelog — Nexus Core

All releases use the canonical `VERSION` file as the single version source.
Derived artifacts (pyproject, installer defaults, .NET project, PyInstaller
backend resource, `.agent/project.json`) are regenerated by
`python scripts/sync_version.py` — run automatically by
`packaging/build_windows.ps1` and verified by `tests/test_version.py`.

## [0.27.0]

**Performance & residency milestone** — one coherent pass over GPU
residency, per-message overhead, startup latency, and the `/api/status`
hot path, verified end-to-end on the installed Windows build (3080 Ti,
12 GB). Total startup **~21.4 s → ~7.0 s**; steady `/api/status`
**~800 ms → ~20–50 ms**; idle footprint 3 processes / ~4.5 GB VRAM;
50-turn soak flat at ~6.1 GB backend RAM.

- **Demand-driven GPU residency** — Chatterbox runs bf16 (~2.3 GB
  resident, from ~3.3 GB) and self-unloads after 120 s idle or under
  VRAM pressure; a `touch=` fix stops status introspection from
  renewing the lease forever (any `/api/voice/status` poll used to pin
  it). `RuntimeManager.vram_releasers` lets LLM launches reclaim idle
  image backends and the voice worker *before* evicting resident
  models. InvokeAI no longer auto-starts at boot — verified on-demand
  round-trip (real PNG, memory freed post-job, llama untouched).
- **Hot path** — per-message `nvidia-smi` spawn replaced with 15 s
  cached telemetry; all subprocess spawns `CREATE_NO_WINDOW` (no more
  console flashes); speech warm-up fires only on a cache-miss enqueue,
  not on every chat message.
- **Startup** — `[nexus-init]` stage timers caught `ProvisioningManager`
  re-verifying every completed item synchronously pre-bind (8.35 s):
  a deep torch import probe, per-item full-registry manifest rescans,
  and sha256 over GBs of weights. Now shallow `runtime_status` for
  boot-time checks, scoped per-manifest refresh, and verified-content
  caches (size+mtime+sha256) — provisioning init **8.35 s → 65 ms**.
  Desktop health poll moved to cheap `/api/health` and WebView2
  environment bootstrap overlaps the backend wait.
- **`/api/status`** — `[nexus-slow]` section timers caught
  `images.summary()` running a live HTTP health probe per backend on
  every call (~2 s each on this box's slow dead-port refusals). Now a
  30 s stale-while-revalidate probe cache with single-flight background
  refresh, parallel probes, bounded timeouts, a dead-Popen busy fix,
  and `_invokeai_models` reusing the probed health instead of
  re-probing on expiry.
- **Voice polish** — Chatterbox loudness normalization to −17 LUFS
  matching system sounds; long list/dictation runs are summarized
  instead of read word-for-word.
- **Verification** — `[nexus-init]`/`[nexus-slow]`/`inventory/<id>`
  diagnostics are permanent and low-volume; `scripts/benchmark.py`
  (startup, idle, latency, voice, soak) plus
  `docs/PERFORMANCE_BASELINE.md` / `docs/PERFORMANCE_OPTIMIZATION.md`
  carry the measured evidence. Full suite 2431 tests green; CI
  `test` + `windows-desktop` (Inno installer + fresh-install/update
  smoke) green on every commit.

## [0.26.1]

**Chatterbox frozen-build fixes** — two defects found by deploying the
installer build rather than trusting the source tree. (1) The worker
script is a `.py` file, which PyInstaller compiles into the PYZ instead
of placing on disk — the spawned runtime got a nonexistent path and
exited instantly. `chatterbox_worker.py` now ships via explicit
`--add-data`, and `_spawn` fails loudly if the script is missing.
(2) Kokoro fallback passed the failed engine's voice id straight
through (`isabella` isn't a Kokoro voice), so a degraded render failed
a second time instead of speaking. The fallback now maps to the closest
Kokoro voice (`bf_isabella` — the approved reference's own source — or
the first available voice). Verified on the deployed install:
Chatterbox synthesized 3.45 s on CUDA (RTF 0.35, 19 tags live) through
the frozen backend.

## [0.26.0]

**Chatterbox Turbo voice engine** — second registered `TTSEngine`,
implemented as an isolated subprocess runtime rather than bundled
dependencies. Torch + chatterbox-tts live in `runtime/voice/chatterbox`
(Python 3.12, torch 2.6.0+CU124) while the frozen backend stays on 3.14;
`ChatterboxEngine` drives a persistent worker (`chatterbox_worker.py`)
with JSONL over stdin/stdout — ping / load / prepare_voice / synthesize
/ capabilities / status / unload / shutdown, structured error responses,
stderr kept off the protocol channel. GPU is opt-in by headroom: `auto`
selects CUDA only when ≥3.2 GB VRAM is free so the LLM/image lanes keep
priority (measured ~2.8 GB resident, RTF ≈0.3 on an RTX 3080 Ti).

**Approved Isabella clone** — the canonical reference is the approved
`isabella-nexus-v6-enhanced-synthetic` render (sha256-verified source
preserved), packaged under `localcodeagent/voice/chatterbox_voices/` so
it ships in the installer like official presets. User-installed clone
voices under `models/voice/chatterbox/voices/` merge with (and can
shadow) official ones; `reference.py` validates duration/clipping/
silence/format before conditioning. Turbo's global conditionals are
re-prepared on voice switch.

**Loudness management** — the quiet-output root cause was Turbo's
reference conditioning (≈ −27 LUFS raw). New pure-NumPy BS.1770 stage
(`voice/loudness.py`, validated within 0.5 LU of pyloudnorm) normalizes
to a configurable target (default −17 LUFS) after output gain and before
the peak limiter. Presets opt in via `normalize_loudness`; existing
presets are untouched. Limiter can be disabled per preset / globally.
Raw −26.8 → −17.0 LUFS measured on live output.

**Emotion & gestures** — `ChatterboxVocalizationAdapter` maps the
existing vocalization planner's semantic styles onto Turbo's native
paralinguistic tags (`[laugh] [chuckle] [sigh] [gasp] [cough] [groan]
[sniff] [shush] [clear throat]` + emotion/delivery tokens), rendered
in Isabella's cloned voice rather than canned samples. A worker-side
tokenizer probe reports which tags are dedicated tokens; Voice Lab
auditions only confirmed ones, with an explicit engine probe for cold
starts. Frequency, cooldowns, persona gating and continuity all ride
the existing VocalizationEngine — nothing about reasoning or visible
chat text changes.

**Safety & integration** — engine failure (missing runtime/model, dead
worker, VRAM floor) degrades to Kokoro via the manager; fallback output
is cached under its own engine key so it never masquerades as Chatterbox
audio. Vocalization adapter follows the active preset's engine, and
previews resolve through the preview preset's engine. StartupNarrator
cache keys are salted with a backend-published engine signature so a
voice switch can't replay stale clips (fault/recovery lines keep a
legacy fallback — silent crash narration is worse). Provisioning gains
two verified items: the standalone CPython runtime (pinned
python-build-standalone, sha256-checked) and the pinned Turbo model
snapshot (9 files, all sha256-verified, idempotent). Voice Studio gets
an engine selector, per-engine voice lists, loudness/limiter controls,
and the Voice Lab. `/api/voice/voices` is engine-aware; new
`/api/voice/capabilities` exposes the capability table.

## [0.25.3]

**Voice trailing-syllable fix** — Kokoro leaves a breathy noise bed
decaying for hundreds of ms after the real last phoneme (audible as a
trailing hiss/mumble), plus dead air the end-slack check previously
bailed on before any tail logic ran. `trim_tail_artifact` now shaves
residue longer than 140ms after the last -22 dB run down to a 90ms
natural decay, then applies the existing detached-phoneme logic to what
remains. Measured on live Kokoro output: 150–500ms tails trimmed on
affected utterances, all words preserved (transcription-verified).
Syllable-length detached islands are deliberately not cut — quiet real
final words are DSP-indistinguishable from strays. New `dsp.DSP_VERSION`
folds into the audio cache key so segments cached under the old pipeline
invalidate instead of serving stale artifacts. Regression-tested in
`test_voice.py`.

## [0.25.2]

**Voice echo fix** — replies that never crossed a sentence boundary
during streaming (unpunctuated text like "Sure thing", or buffered
tails) were spoken **twice**: `finish_task` checked the emitted count
*before* `flush()`, so the flush tail spoke the text and the
`final_text` fallback then enqueued it a second time. Emissions are now
counted after the flush; the fallback only fires when nothing was
spoken at all. Regression-tested in `test_voice.py`.

## [0.25.1]

**Chat layout fix** — streaming responses that append adjunct elements
(live research card, action/inline controls, feedback row, retry button,
memory badge) into the `.message` grid auto-placed them into the 42px
avatar track; a research card inserted first would shove the entire
reply bubble into a 42px-wide column ("scrunched" layout + mangled
controls) until navigation re-rendered the message without them. All
non-avatar children are now pinned to the content column.

## [0.23.0]

**Nexus self-knowledge + universal chat control plane** — chat is now a
first-class control surface: Nexus answers "what can you do", "what's
broken", "where is X" from a live Feature Catalog composed against the
Capability Registry, and executes safe registered actions directly
("turn voice off", "use Isabella", "set workers to four").

- **`self_knowledge/` package** — `FeatureCatalog` (every user-facing
  feature with dev status + live runtime probe), `PageRegistry`
  (canonical routes + deep links like `/settings.html#voice`),
  `SettingsRegistry` (chat-mutable `SettingSpec`s with coercion and
  read-back verification), `ActionRegistry` (typed `ActionSpec`s with a
  risk ladder: read_only → low_risk → confirm → sensitive →
  destructive), and `SelfKnowledgeService` (NL resolution → answer /
  execute / propose / navigate).
- **Orchestrator lane** — `_self_knowledge_reply` runs in Tier 0 before
  the canned-suppression gate so control requests classified as action
  intents still resolve locally; renders through the persona genome
  (wording, never truth); `ui` payload carries action cards, deep links,
  and inline controls through `AgentResult.ui` → response `ui`.
- **Chat follow-ups** — `do it` runs the pending proposal, `undo that` /
  `turn it back on` restore the previous value, `open it` navigates the
  last deep link. Follow-up context lives on the service.
- **Truth guarantees** — questions never mutate ("what's the image
  backend" returns a value, not a setter call); capability claims match
  the probed runtime state exactly (`setup_required`,
  `authorization_required`, `broken`, `experimental`); imperatives fall
  through to the tools/model lane unless they resolve as control.
- **API** — `GET /api/features`, `/api/features/{id}`, `/api/pages`,
  `/api/actions`, `/api/settings/registry`, `POST /api/actions/execute`
  (id-validated, risk-gated, verified).
- **Frontend** — `renderChatUI()` renders action cards, deep-link
  buttons, and inline toggle/select/slider controls under assistant
  messages; every control posts through `/api/actions/execute`.
- **Docs** — `docs/NEXUS_SELF_KNOWLEDGE.md` (catalog + lane), `docs/
  CHAT_CONTROL_PLANE.md` (actions, risk, verify, UI contract).
- **Tests** — 30-case suite covering the acceptance matrix: catalog
  truth, dev-vs-runtime separation, verified mutation, confirmation
  gates, sensitive-action refusal, follow-up resolution, deep links,
  and the "questions never mutate" rule.
