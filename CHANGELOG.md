# Changelog — Nexus Core

All releases use the canonical `VERSION` file as the single version source.
Derived artifacts (pyproject, installer defaults, .NET project, PyInstaller
backend resource, `.agent/project.json`) are regenerated by
`python scripts/sync_version.py` — run automatically by
`packaging/build_windows.ps1` and verified by `tests/test_version.py`.

## [0.15.0] — Unreleased

- **First-class requirements** (`localcodeagent/requirements.py`) — vague
  goals now become durable, inspectable requirement rows with lifecycle
  (`not_started → planned → in_progress → implemented → verified /
  failed / blocked / deferred / rejected`), evidence entries, and
  provenance that marks every derived row `inferred`. "Fix startup" /
  "make this work" style asks derive acceptance criteria *before* work
  begins: mission creation links requirement IDs onto each success
  criterion, `/api/chat` repair asks persist rows scoped to the task and
  return `acceptance_criteria` in the response, and SSE streams emit a
  live `requirements` event. The evaluator carries `requirement_id`
  through criterion results so `RequirementStore.sync_mission` flips
  rows to `verified`/`failed` from real evidence — never self-reported
  success. API: `GET /api/requirements`, `POST /api/requirements`,
  `POST /api/requirements/status`, `POST /api/requirements/evidence`;
  the mission detail page renders a live requirements checklist with
  inferred badges. Docs: `docs/REQUIREMENTS.md`.
- **Hypothesis engine + causal memory + decision journal**
  (`localcodeagent/hypotheses.py`, `causal.py`, `decisions.py`) —
  failures now produce first-class hypothesis rows with a persisted
  lifecycle (`proposed → testing → supported/weakened →
  confirmed/rejected`), evidence-for/against audit lists, and
  discriminating-test selection that prefers checks ruling out the most
  competitors. `CausalMemory` stores mechanism-level chains
  (symptom → root cause → mechanism → fix → verification) and seeds the
  next diagnosis as *ranked priors* — candidates to test, never assumed
  causes. `DecisionJournal` records problem/alternatives/evidence/
  decision/expected vs actual outcome. `SelfRepairCoordinator` wires all
  three: diagnosis merges causal priors and upserts hypothesis rows;
  resolution confirms the winner, rejects the losers, and writes the
  causal record. API: `/api/hypotheses` (+ status/evidence/test),
  `/api/causal-memory`, `/api/decisions` (+ outcome). Docs:
  `docs/REASONING.md`.
- **Multi-domain mission decomposition** — the planner fans multi-domain
  objectives ("audit backend, UI, and tests") into parallel scoped lanes
  that converge on `integrate` → `review` → `verify` node kinds
  (integrator/reviewer worker roles, agent-lane executed). Callers may
  attach explicit `decomposition` lanes via the missions API.
- **Plan versioning** — every plan build/replan bumps `plan_version` and
  records `plan_history` (version, reason, node count, lanes), so plan
  evolution is inspectable rather than opaque.
- **Project-linked missions** — `project_id` on missions injects a
  bounded `ProjectStore.context_digest` (goals/decisions/blockers) into
  work instructions; finished nodes write to project worker history and
  mission completion logs to project activity. Projects gain
  `status`/`goal-complete` actions and a `/projects.html` page.
- **Code intelligence** — `code_references` + `code_impact` tools:
  word-boundary definition/reference scan across the tree (AST /
  tree-sitter / regex backends reported honestly), importers, dependent
  files and covering tests for blast-radius estimates before edits.
- **Speech-to-text** — `/api/stt` status, `/api/stt/transcribe` (push-
  to-talk blob → faster-whisper/vosk), `/api/stt/session` hands-free
  loop with SSE `stt_utterance`/`stt_partial` events. Chat gains a mic
  button (hold-to-talk or click-to-toggle) that hides when no local STT
  backend exists. `stt_backend`, `stt_model`, `vosk_model_path`, and
  `stt_auto_submit` are real config fields; the `voice-stt` extra pins
  `sounddevice==0.5.6`, `faster-whisper==1.2.1`, and compatible
  `av==18.1.0`.
- **Operational state + return briefing** — `nexus_state.py` derives a
  structured snapshot (focus, worker load, queue depth, resource
  pressure, next action, away flag) at `/api/nexus/state`, surfaced in
  Mission Control; `/api/briefing` produces a deduped "while you were
  away" digest shown once per session in chat after ≥20 min idle.
- **Mission checkpoints** — every finished node appends a bounded
  checkpoint (node, state, plan version) so restart forensics can answer
  "what was the mission doing when it stopped".
- **Knowledge Library** (`localcodeagent/library.py`) — managed document
  ingestion: external files extract through `extract_document_text`,
  catalog with checksum + origin + project ownership, and index into the
  shared knowledge index as `lib:<id>` entries. `refresh()` re-checks
  origins — changed docs reindex, missing ones go stale (chunks stop
  matching, provenance stays). `knowledge_search` gains `project`
  scoping; `/api/library` exposes list/detail/import/refresh/reassign.
- **Structured correction learning** (`localcodeagent/preferences.py`) —
  explicit behavioral corrections become scoped candidate preferences
  instead of silent permanent rules. Repeated evidence or explicit user
  activation promotes a bounded prompt overlay; users can inspect,
  activate, pause, edit, re-scope, or forget rules from Settings →
  Profile → Learned Preferences. Unsafe corrections that target
  permissions, safety, secrets, or creator-locked identity are refused
  before storage, and project/profile scopes remain isolated.
- **Permission-gated desktop control hardening** — desktop actions split
  into granular Settings → Permissions keys (`desktop.view`,
  `screen.capture`, `desktop.control`, `mouse.control`,
  `keyboard.control`, `clipboard.read/write`, `application.launch`), with
  legacy `computer.observe`/`computer.control` aliases preserved. Adds
  active-window identification and shell-free app launch; validates window
  handles, virtual-screen coordinates, mouse buttons, scroll bounds, and
  key combos; closes every action's activity row as completed/failed; and
  redacts typed/clipboard payloads while retaining bounded audit metadata.
- **Avatar animation/lip-sync foundation** — `NexusAvatar` now exposes
  bounded `idle|listening|thinking|speaking` activity alongside semantic
  expressions; voice lifecycle and gesture events feed it without carrying
  speech content. The chat top bar gains a canonical-portrait presence
  (`web/avatar.js`) that reflects actual playback for lightweight lip-sync,
  push-to-talk/listening state, active agent thinking, gesture motion, and
  operational mood. CSS-only motion honors reduced-motion settings and
  falls back to the static portrait.
- **Managed skill/plugin lifecycle** — skill packages now expose
  author/provider, capability, tool, permission, dependency, OS, update,
  UI, and health metadata through `GET /api/skills[/name]`. The System page
  supports verification plus `skills.manage`-gated install, update,
  enable/disable, bounded rollback snapshots, and removal; approval
  responses disclose requested permissions/capabilities, broad permission
  declarations are rejected, and executable health checks require the
  separate `shell.execute` gate.
- **Self-repair rollback hardening** — promotion now stages verified LKG
  snapshots and fails closed if preservation fails. Snapshot manifests are
  treated as untrusted on restore (bounded size/files, normalized paths,
  protected `.git`/worktree roots, digest verification) and restores verify
  every target afterward; retention stays bounded. `retry`, `process`,
  `rollback`, and `abandon` API actions now require the `repair.manage`
  hard gate, which autonomous mode never auto-grants.
- **Long-duration autonomy hardening** — mission approval waits share the
  autonomous approval timeout, recover by replanning if their durable row
  is missing, and are bounded by `max_approval_retries` so unattended runs
  cannot re-ask forever. Autonomy store retention now preserves live
  missions, pending approvals, and open repair incidents instead of
  evicting them behind newer history.
- **Mission model installs** — `model_install` mission jobs resolve LLM
  catalog IDs through the checksummed coding-model manager before falling
  back to image profiles. Catalog and image-library startup now remove
  orphaned `.part` downloads left by a process kill so resumed missions do
  not accumulate large stale temporaries.
- **Local interop/indexing provisioning** — the `code-intel` extra pins
  tree-sitter core/JS/TS/Python grammars and `python-lsp-server`; real
  validation covered tree-sitter extraction and a pylsp definition,
  references, hover, symbols, and diagnostics round trip. MCP interop was
  also exercised against official filesystem (stdio) and everything
  (Streamable HTTP) servers.
- **Workstation-depth isolated validation** — the self-update validator now
  smoke-checks every primary UI page and the autonomy, tools/plugins, MCP,
  projects, knowledge/library/preferences, STT, operational-state,
  task/activity/queue, process/resource, and readiness APIs on a second
  process. Validator and CI-log capture decode external output safely on
  Windows instead of letting non-CP1252 bytes kill the reader thread; the
  Windows package/installer contract now requires every bundled workflow
  (including the verified Real-ESRGAN post-process path), and direct
  Python/.NET/Inno build/test inputs are pinned for reproducible artifacts.
- **Resource/runtime controls** — a new `runtime.manage` permission key
  (ask in every shipped profile, and in `AUTONOMY_NEVER_AUTO` so unattended
  mode cannot self-grant it) now gates `POST /api/processes/action` and
  `/api/runtime/start|stop`; the Tools/Models pages confirm and resend with
  `approve: true`. `ProcessManager.list()` reports live per-service
  `resource` usage (RSS/commit MB + cumulative CPU seconds via Win32 or
  /proc, no psutil), `HardwareSnapshot` carries CPU name/cores, pagefile,
  uptime, load average, and a derived `ram_used_percent`, `/api/resources`
  includes the managed process list, and nvidia-smi output decodes
  UTF-8-safe on Windows. External runtimes still refuse control even after
  approval, and internal idle-eviction paths are unaffected.
- **Creator Brain live dogfood** — `/api/nexus-brain` lifecycle coverage
  over real HTTP: initialize issues a creator session, staged facts/rules/
  corrections/sourced-knowledge/conversations all sync into the signed
  store with verified counts, banked records reach `prompt_context`/
  `knowledge_context`/`training_context`, the `web_research` subroutine
  blocks `/api/research/plan` with a structured 403, and locking retires
  the session token. The signed-export distribution path is dogfooded too:
  a second live server installs the export read-only via
  `/api/nexus-brain/import`, tampered payloads answer 403, and a fresh
  Brain object on the installed file reloads verified. Permission-gated
  Brain routes now answer 403 for missing/false sessions rather than 500.
- **Conversation-learning dogfood** — real `/api/chat` training turns
  ("remember that…", "always…", "no, you should…") exercise
  `learn_from_user` end to end: facts/rules/training examples persist,
  reach `prompt_context` and `/api/conversation-memory`, and reload
  verbatim after restart. Model-replacement continuity is dogfooded too —
  memory staged under `model-alpha` survives a full restart under
  `model-beta` with the Brain still verified.

  admission control replaces the static resource-mode worker count. Every
  unit of work reserves measured CPU/RAM/VRAM/GPU/model-slot capacity

  branches, shared-file hotspot detection, scope-overlap detection, and

- **Queued-task voice notice** — user-initiated work that can't start

## [0.12.1] — Unreleased

- **In-memory stores now match their persisted bounds** — `TaskStore`
  kept every row ever created in RAM while the file held at most
  ~100 terminal + non-terminal rows; the store now evicts rows past the
  persisted set on save. Image `_jobs`, install `_cancel` flags, and
  task transcript `_log_buffers` had the same divergence — buffers now
  flush on every terminal status transition (previously only on
  empty-transcript stubs), image jobs evict past the 500-row tail, and
  cancel registrations pop on worker exit.
- **Append-only logs and spawned-job markers are bounded everywhere** —
  `permission_audit.jsonl`, eval history, and the cerebellum optimization
  log grew a line per event forever (eval `history()` also re-read the
  whole file per call); all now compact to their tail windows. Runtime
  probe logs leak a handle per benchmark and accumulated files — the
  handle travels with `_Probe` and closes in `stop()`, and `probe-*.log`
  prunes to the newest 20. Marker-then-spawn failures no longer wedge
  work: mission `_workers`, image jobs, model installs, MCP and LSP
  reader threads, and the queue/retry sets all pop markers, mark the
  unit failed, or kill the orphaned PIPE'd child when `Thread.start()`
  raises.
- **Mission attribution is task-scoped, not a mutable global** — the
  mission executor stamped `current_mission_id` on the orchestrator
  before `run()`; under parallel lanes a concurrent chat drive inherited
  the stamp and one node's cleanup cleared another's attribution
  mid-flight. `run(mission_id=…)` now registers the mapping per task
  (released on session close); `_act` prefers it over the legacy global.
- **Worker-spawn marker leaks closed** — `_queue_running.add()` and
  `_retrying_tasks.add()` ran before `Thread.start()`; a failed spawn
  leaked the marker forever, permanently wedging `_dequeue_next` and
  excluding the task from retries. The queue path also silently dropped
  the popped item — it now re-enqueues before propagating.
- **Concurrent resume/recover calls can no longer double-drive a task** —
  `resume()` claimed `session.pending_approval` non-atomically, so two
  simultaneous approvals both executed the action and entered competing
  drives on one session; driver registration was also unconditional.
  New `_claim_drive()` single-flights under `_drive_lock` (same-thread
  re-entry allowed for nested resume paths), the approval claim happens
  under the same lock, and all three resume branches — session tool,
  persisted tool/verification, and direct image — flip the ledger to
  `running`/`working` at claim time so approval-expiry can't reap a
  task mid-execution.
- **Cancelling a parked task releases its session** — `/api/jobs/cancel`
  flipped the ledger row to `cancelled` but left the session in
  `_sessions` (leaked memory, resumable stale state) and kept
  `pending_approval` in the row. The endpoint now drops the session and
  clears the field — a parked task has no live drive to notice.
- **All task status scans now use the full ledger** — auto-resume,
  approval-timeout expiry, error-retry candidates, eviction busy-set,
  lane activity, and the stalled-task reaper each read a bounded
  `recent(50)` window, so tasks pushed past it by newer rows became
  invisible. New `TaskStore.by_status()` scans the whole ledger; every
  correctness-sensitive query uses it (`recent()` remains for display
  payloads only).
- **Non-terminal tasks can no longer be dropped from `tasks.json`** —
  persistence kept only the newest 100 rows; a long-running or parked
  task pushed past the tail vanished on restart and was unrecoverable.
  Rows in `running`/`verifying`/`reviewing`/`waiting_approval`/
  `interrupted` are always written, in order.
- **Identical failing tool calls are dedup-blocked, and stalled
  escalations now nudge the model** — a live task retried the same
  failing `apply_patch` five times, each round parking for approval and
  burning a step until `step_limit`. A call whose `(name, arguments)`
  signature already errored is fed back as an error without executing
  (signatures reset after any successful mutating call so
  retry-after-change still works), and when `failures >= 2` resolves
  to the same model the corrective hint is injected once instead of
  the escalation silently no-oping.
- **Memory-pressure eviction can no longer kill a serving runtime
  mid-request** — recovered/resumed tasks could drive with
  `model_id=""` on the ledger row, so the eviction busy-set never
  pinned their model; when free VRAM dipped below
  `memory_pressure_vram_gb` during a 17k-token prompt the manager
  stopped the very llama-server answering the request (repeated
  `connection_reset` on :8081). `_drive_or_error` now restamps the
  routed model at every drive start, and the busy-set conservatively
  pins all resident models while any live driver's model is
  unattributable.
- **Step-limit completion no longer crashes recording memory** — the
  step-limit path passed `conversation_manager` kwargs to
  `ConversationMemory.record_exchange` (a 2-arg method); the TypeError
  flipped `step_limit` tasks to `error` and skipped the manager record.
  Both stores now record via the canonical two-call pattern.
- **Dead driver no longer wedges the task queue** — approving a
  verification command whose run failed started an automatic repair
  round, but `resume()` returned `_finalize()`'s internal `None`
  straight to the HTTP handler, which then died on `result.content`.
  The task stayed `running`/`researching_failure` forever with no live
  thread, and the single-flight queue refused to start queued work.
  `resume()` now re-enters the drive loop on that signal, and a driver
  registry plus watchdog reaper marks any active task whose driver
  thread vanished as `error` after `stalled_task_grace_seconds` (120s
  default, min 15s) so the queue always moves on. `waiting_approval`
  remains a legitimate parked state and is never reaped; live drives
  are identified by their registered thread, not elapsed time.
- **Single-flight now holds past the ledger window** — dequeue and
  error-retry blocked on `recent(20)`/`recent(50)` statuses, so enough
  newer task rows could push a genuinely active task out of the window
  and let a second drive start (model thrash). The driver-thread
  registry is now the authoritative liveness check in both paths, the
  reaper scans the wider window, idle-model eviction pins live-driver
  models, and one `_agent_lane_active()` helper now guards mission
  dispatch and auto-tune benchmarking with the same semantics.
- **Answer Memory self-heals partial schema stamps** — migrations are
  keyed on `PRAGMA user_version`, so a database stamped v2 while missing
  a `profile_id` column (interrupted migration, manual stamp, partial
  restore) reported current while every profile-scoped write failed.
  The column assertions now re-run idempotently on every open.
- **Canary could validate the wrong code** — the production candidate
  launcher prepended the worktree to an inherited `PYTHONPATH`, so any
  harness that exports the repo path (the selftest runner does exactly
  that) let the canary silently boot `localcodeagent` from stable-repo
  code and report healthy for a worktree that couldn't boot.
  `PYTHONPATH` is now replaced with the worktree path so candidate
  resolution is fully isolated.
- **Personality presets were inaudible** — 70 of 73 presets shipped with
  empty voice controls, so switching personalities changed nothing a
  listener could hear. Style families now map to sensible voice defaults
  (calm=slower/softer/longer pauses, playful=faster/more expressive,
  professional=moderate/controlled, nerdy=energetic/clear emphasis);
  explicit per-preset voices still win and values stay within
  intelligible bounds. Verified live: identical phrase renders 3.48s
  under Calm vs 3.05s under Playful.
- **Personality prompts were cosmetic** — standout sliders now render as
  prescriptive delivery cues ("tease with sharp playful sass", "keep
  answers short") instead of only a name plus numbers, so selected
  personalities measurably change real chat responses while the
  delivery-style-only boundary still guards facts, code, and permissions.
- **Profile memory leak through Answer Memory (privacy fix)** — learned
  answers and experiences are now stamped with the profile that recorded
  them (`profile_id`, schema v2). Retrieval, learned-answer lists, forget,
  corrections, and feedback only see unscoped rows plus the active
  profile's rows, so a personal answer learned under one profile can no
  longer be served to — or mutated by — another profile through trusted
  bypass or prompt-context hints. Unscoped rows (recorded before profiles
  or with no active profile) remain shared, preserving general technical
  knowledge.

Installer update UX — update-time operations that previously ran with a
static wizard (looking frozen) now report exactly what Setup is doing.

### Fixed

- **Silent update delay** — `PrepareToInstall` now shows live stage text on
  the wizard while Setup closes running Nexus Core processes (graceful
  shutdown → grace period → forced cleanup of backend/llama children), and
  the grace sleeps are chunked so the wizard keeps repainting.
- **Silent multi-GB SHA-256 checks** — when an existing model lacks trusted
  catalog metadata, Setup now shows "Verifying existing model file…" with the
  filename and size before hashing, instead of sitting motionless for minutes.
- **"DeleteFile failed; code 5" during update** — an orphaned backend could
  survive the image-name taskkill sweep and keep `ChatNexus.Backend.exe`
  locked mid-install. Setup now also kills the backend pid recorded in
  `data\logs\backend.pid`, sweeps every process whose executable lives under
  the install directory via PowerShell, and probes the replaceable binaries
  for write locks — waiting up to 45 s with visible status before Inno
  starts replacing files.
- **Misleading second progress bar** — removed; the native Inno gauge is the
  single progress indicator and already tracks extraction and external
  downloads. Stage text through the Inno-owned file-analysis window
  ("Analyzing files to update…") keeps the Ready page honest instead.
- **"Nexus Core could not start" after update** — `ensure_ready` held the
  runtime-manager lock for the entire llama-server load (up to 180 s per
  attempt, three fallback attempts), and `/api/status` shares that lock.
  Boot-time model prewarm and interrupted-task auto-resume triggered the
  load on every launch, the host health check timed out, the backend was
  killed, and the loop repeated. Model loads now run the wait lock-free
  behind a per-model single-flight claim, `statuses()` falls back to
  last-known state under contention, and the host health-probe timeout
  was raised (2 s → 10 s request, UI probe 5 s → 15 s).
- **Orphaned backend reaping** — the host also sweeps processes matching
  the backend exe path, not just the recorded pidfile entry, so backends
  orphaned outside the normal launch path can't hold shared state.
- **Silent failure on post-install launch** — the installer's Run entry
  fired ~2 s after files landed, inside the window where Defender still
  scans the freshly-written backend exe; `File.Exists` returned false and
  the host threw "backend executable is missing" *before* writing a single
  log line. The host now writes `backend start requested` first, then
  waits up to 30 s for the exe to settle, and `Main` records a
  first-breath `host process started` marker so "never ran" vs "died in
  UI init" are distinguishable.
- **Empty host log after launch failure** — the desktop host now writes state
  notes, launch intent, and failure reasons to `backend-host.log` *before*
  `Process.Start`, so a launch that dies early no longer shows "check the
  log" over an empty file. Health-check stalls also log the last probe
  result (HTTP status or exception) every 15 s.

## [0.12.0] — Unreleased

Profiles + Creator Identity + Personality Studio + First-Run Onboarding —
Nexus Core now runs on durable human profiles. A fresh install boots
locked into a Start Here onboarding flow; creating a profile unlocks the
workstation. Personality presets, sliders, strength, mood, voice
delivery, greetings, personal memory, and settings are all per-profile
and survive restarts.

### Added

- **`localcodeagent/profiles/`** — durable UUID-keyed profiles under
  `data/profiles/<uuid>/` (profile.json, avatar.webp, personality.json,
  voice.json, settings, memory/). Identity fields (name, sex, birthdate)
  are immutable after creation; contact/location stay editable; age is
  always derived from the birthdate — never stored.
- **Start Here onboarding** (`web/start.html`) — required-field form
  with leap-aware birthdate dropdowns + live age, searchable state/city
  lists backed by a bundled offline dataset (51 jurisdictions, ~1.7k

  candidate when a draft model is configured — each measured with a
  bounded probe (cold + warm request: TTFT/prompt-TPS/gen-TPS/cached
  tokens).
- **Provable-failure blacklist**: `mark_bad()` records tuned configs that
  OOM/crash on the real launch path; `tuned_flags()` never re-picks them.
  `classify_launch_error()` tags probe failures as oom/crash/timeout.
- **Launch fallback ladder**: `_launch_with_fallback` tries tuned →
  heuristic-safe → bare flags; a bad benchmark result can no longer brick
  model startup.
- **Dynamic context growth**: `ensure_ready(profile, min_context=...)` —
  a task needing a larger window relaunches the resident server at the
  larger class instead of silently truncating. `context_class()` maps
  estimated prompt size to small/medium/large/xlarge.
- **Cold/warm telemetry**: `record_generation` records `cold` (model
  loaded for this request), `context`, `cached_tokens`, and the resolved
  launch surface (gpu_layers/threads/batch/ubatch/flash_attn/kv/
  speculative). `generation_summary` reports cold vs warm TPS and
  prompt-cache hit counts; measurements feed the Digital Twin.
