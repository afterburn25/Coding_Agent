## [0.42.0]

**Adaptive Intelligence — Phase A: persistent identity, capability
truth, and a live situation model.** The first stage of the
experience→evidence→lesson→improvement program: one authoritative
Identity Manager for the accounts Nexus holds, a dependency-aware
Capability Truth Graph, and a Situation Model that answers "what's
going on?" from measured state.

- **Identity Manager** (`identity_mgr.py`) — durable
  `data/identity.json` registry of service accounts: canonical agent
  name, primary email + backing account, recovery ownership (always
  the user), per-account handle/state/auth-method/scopes/provenance/
  health/last-success, and an audit trail. Credentials are vault key
  *references* only — secret values never enter the store. Live rows
  merge GitHubAccountService + connector account probes so stale
  records lose to observed state.
- **Account creation workflow** — `begin_account_creation` gated by
  the new `identity.account_create` permission (a distinct authority
  from `social.post`/`browser.control`); CAPTCHA/phone/ToS/security
  challenges park the flow at `awaiting_human`; `verify_login` flips
  `active` only after a real authenticated probe — accounts are
  claimed, never asserted.
- **`identity.*` permissions** — `read` / `account_create` /
  `account_modify` / `account_delete` / `recovery_modify` /
  `oauth_connect` with PERMISSION_INFO metadata; all mutations are in
  `AUTONOMY_NEVER_AUTO` and denied under the offline profile.
- **Capability Truth Graph** — the registry grows dependency edges
  (`depends_on`), five new probed states (`permission_required`,
  `disconnected`, `temporarily_unavailable`, `policy_denied`,
  `unsupported`), `engine` naming (Playwright, InvokeAI…),
  `checked_at`/`verified_at` timestamps, `blockers()` — a failing
  dependency chain explains *why* a capability is down — and bounded,
  rate-limited `run_selftest()` hooks that verify a capability by
  exercising it.
- **Situation Model** (`nexus_state.build_situation` /
  `situation_text`) — conversation topic + goal from the state graph,
  active/paused missions with workstream counts, running jobs /
  installs / downloads, resident models, pending approvals, connected
  services, waiting peer consults, recent failures, current project.
  `situation_text` renders one compact honest answer — no JSON dumps.
- **"what's going on?"** chat lane answers from the situation model.
- **Intelligence Center** — new `web/intel.html` (Situation /
  Capabilities / Identity tabs) wired into the primary nav on every
  page.
- **Endpoints** — `GET /api/situation`, `GET /api/identity`,
  `GET /api/identity/audit`, `GET /api/capabilities/graph`,
  `POST /api/capabilities/selftest`, `POST /api/identity/account/
  create|human-gate|resume|verify|remove`, `POST
  /api/identity/primary-email`.
- **Fix — InvokeAI CPU-only torch**: the tool manifest had no PyTorch
  CUDA index, so the dedicated venv installed `torch +cpu` even on GPU
  hosts (observed live: every SDXL job grinding ~60–100s/step until the
  job timeout fired). `pip_args` now adds the `cu130` wheel index.
- **Fix — orphaned backend work after cancel/timeout**: InvokeAI
  persists its queue in sqlite and *resumes* in-flight items on
  restart. A Nexus-side cancel that never landed (backend
  crash-looping) left a 30-step CPU job grinding ~40 min across a
  process restart. Job failure/timeout now best-effort cancels the
  queue item, and cancels that fail against an unreachable backend are
  persisted to `pending_cancels.json` and flushed once the backend is
  healthy again.
- **Fix — fleet profiles lacked resource estimates**: synthesized
  InvokeAI profiles never copied `estimated_vram_gb`/`estimated_ram_gb`
  from the fleet spec, so the pre-job arbiter had nothing to act on and
  jobs ran against a resident LLM's VRAM. Verified live: 768×768/6-step
  RealVisXL job on the RTX 3080 Ti finished in 28.9 s end-to-end
  (10.5 s graph) producing a real PNG.
- **Fix — deploy relaunch gap**: a locked file mid-mirror (robocopy
  rc≥8) threw after stopping the app but before relaunching it; the
  failure path now relaunches NexusCore.exe before throwing.

## [0.40.0]

**Engineering Missions.** The autonomy layer graduates from a flat task
graph into a durable engineering hierarchy — Mission → Workstream →
Task → Subtask → Verification — with context that lives on the mission
record, not in any model's context window. A broad request like
"refactor the backend, update the UI, write the tests, build the
installer" now decomposes into parallel workstreams with their own
scopes, priorities, and acceptance criteria, and keeps running for
hours across restarts.

- **Durable workstreams** (`autonomy/missions.py`) — first-class
  workstream records (title, scope patterns, role, priority, status,
  acceptance criteria, per-lane progress rollup) persisted on the
  mission; linked tasks aggregate into `planned → active →
  awaiting_review → integration_ready → integrated` automatically as
  the graph runs.
- **Acceptance criteria before implementation** — the planner derives a
  structured completion contract from success criteria, constraints,
  and decomposition before workers start; a mission cannot complete on
  worker prose alone — `MissionEvaluator` still gates on machine-checked
  criteria.
- **Mission context capsule** — compact continuation record (objective,
  criteria, decisions, completed/active workstreams, known failures,
  blockers, relevant symbols) rebuilt on a staleness timer and injected
  into each worker's prompt, so mission lifetime is independent of any
  model's context window. `maybe_compact()` preserves raw history
  verbatim and never discards criteria, security constraints, or user
  decisions.
- **Per-task context packages** — each worker receives only its
  workstream's slice: lane objective, its acceptance criteria, scoped
  decisions, relevant failures, and a NEXUS.md excerpt — not the entire
  mission history.
- **NEXUS.md discovery** — repo-local operating instructions
  (architecture, build/test commands, invariants) are discovered at
  workspace root and folded into worker context; guidance, never an
  override of hard policy or permissions.
- **Durable decisions** — `record_decision` stores engineering rulings
  with reason/source/supersession; active decisions auto-inherit into
  every worker's context package.
- **File/symbol ownership with leases** — workers reserve path globs
  before dispatch; overlapping reservations park the contender
  (queue_reason `ownership_conflict`), leases heartbeat and expire, a
  sweep reclaims dead workers' scopes, and completions release. No
  silent concurrent overwrites.
- **Live steering** — `steer(mission_id, "pause the frontend")` /
  `forget the voice work` / `make installer the priority` map to
  pause/resume/drop/reprioritize ops on matching workstreams without
  restarting the mission; exposed via `POST /api/missions/:id/steer`,
  per-workstream POST ops, and chat phrasing.
- **Thrash detection** — repeated identical failure signatures
  (`fail_sig_count ≥ 2`) stop the retry loop, escalate the node to the
  deep model tier, and record a thrash event; escalation count tracked
  in mission metrics.
- **Git checkpoints** — automatic `nexus/<mission>/<label>` tags at
  baseline and final; labels recorded on the mission for rollback.
- **Goal-drift probe** — periodic check comparing active task titles
  against the objective; unrelated work is flagged `goal_drift` in
  history and metrics instead of silently running.
- **Missions UI** — workstream cards with per-lane progress, priority
  pills, acceptance criteria, and inline Pause/Resume/P0/Drop controls;
  a context section showing decisions, known failures, blockers, and
  compaction/escalation/conflict metrics.
- **Mission metrics** — compactions, repair cycles, escalations,
  ownership conflicts, checkpoints — the raw material for scheduling
  tuning (§44).
- **Requirement-change propagation to the hierarchy** — supersession now
  reaches workstream acceptance rows (`requirement_flags`), mission
  acceptance criteria (stale criteria leave the live contract), and
  durable decisions (auto-superseded), on top of per-node
  `stale_requirement` marking.
- **Review evidence packets** — review/integrate workers receive a
  per-predecessor outcome + files-changed digest in their context
  package, so "independent review" audits real artifacts.
- **Workstream worktrees (§13–14)** — multi-lane missions provision one
  isolated checkout per workstream (`nexus/<ws>/<slug>` under
  `.nexus/worktrees`); lane diffs commit on the lane branch; the
  integrate node merges branches mechanically and surfaces conflicts;
  integrated lanes tear down cleanly while dirty worktrees are never
  force-deleted.
- **Live model routing (§9–10)** — node `model_role` flows through
  `agent.run(model_role=…)` to the router as a tier override; thrash
  escalation and the review lane now genuinely reach
  `deep_reasoner`-tier models. Dispatch batches the hot model tier
  within a priority band (§31).
- **Deploy hardening** — `deploy_local.ps1` reaps backend helper
  children + orphaned selftest/unittest processes whose locks twice
  failed the mirror (rc=11).

## [0.39.0]

**Peer Intelligence Network.** Moltbook graduates from "a place Nexus
can post" to a genuine peer-learning network: a durable peer graph,
expected-value consultation, domain-scoped trust, debates that keep
both sides, a replication ledger, and missions that park on external
answers without freezing.

- **Peer Intelligence Graph** (`social/store.py`) — every known agent
  is a stable dossier: relationship dimensions (familiarity, respect,
  trust, reciprocity, communication quality), per-domain expertise
  with evidence counts, disagreements, shared discussions, open
  questions, manipulation flags, follow-up intent with bounded pursuit
  (attempt cap + cooldown — no creepy re-messaging), and
  want-to-evaluate marks. `peer_card()` is the UI dossier; trust is
  agent × domain, never global.
- **Earned expertise** — `update_expertise` moves confidence on real
  outcomes only: claims promoted to tested/verified/applied raise it,
  refuted claims and failed advice lower it, manipulation strains the
  relationship. Claimed expertise earns nothing.
- **Claim dedupe** — identical claim text from multiple peers merges
  into one record with a corroboration entry; consensus ≠ truth, so
  copied claims never count as independent evidence.
- **Claim ladder** — `heard → corroborated → testable → tested →
  verified → applied`, plus `retired`/`refuted` terminal rungs.
  HEARD claims never reach trusted knowledge.
- **ConsultEngine** (`social/consult.py`) — expected-value gating
  (gap × importance × peer relevance × information gain), domain-aware
  peer selection excluding strained/manipulation-flagged agents, a
  `sanitize_question` builder that strips private paths/addresses and
  oversized code blocks before the outbound secret scan, and durable
  consult records with deadlines and continuation policy.
- **Mission external-wait** — a repeatedly-stuck mission (≥2 replans)
  may open a peer consult; a parked `external_wait` node watches it.
  The mission continues every other ready node — it never freezes.
  A peer reply resolves the node; a deadline resolves it "unanswered".
  Answers land in node output tagged UNTRUSTED.
- **Reply matching** — inbound notifications match awaiting consults
  by target peer or thread ref; the answer records provenance and
  bumps `replies_received`. Injected replies flag the peer's
  manipulation record and strain trust — never authorize anything.
- **Teaching + corrections** — `teach_postmortem` self-checks
  ("do I have evidence?") before publishing sanitized writeups;
  `correct_record` appends transparent corrections rather than
  silently editing history. Both pass the outbound secret scan and
  the permission gate.
- **New social queries** — deterministic, provenance-grounded answers
  for "what have you learned from other AIs" (journal + claim ladder),
  "who do you trust" (per-domain evidence, no global trust number),
  "who are your friends" (real interaction history, follow-up intent),
  and "ask the community about X" (EV-gated consult through the
  `social.post` approval lane).
- **Claim-link grounding fix** — a live dogfood found the model
  inventing "I sent the claim link to your browser" (no such action
  exists). New `claim_link`/`account_state` lanes answer from live
  connector state and deliver the literal claim URL; bare "resend it"
  only binds when a claim is actually outstanding.
- **API + UI** — `/api/social` gains peer dossier, consults
  (list/dispatch/follow-up), debates, journal, experiments, councils,
  and interest-graph endpoints; `social.html` grows Ask-the-network,
  Debates, Learning Journal, Replication Experiments, Interests and
  Councils panels.
- **Epistemic backlog** — richer lifecycle (identified → researching →
  peer_consultation → awaiting_response → testing → verified /
  rejected / unresolved), verification plans, candidate peers, and
  related-mission linkage.

## [0.38.0]

**Live Capability Grounding + Social/Epistemic Drives.** Capability
answers now come from probed runtime state, never stale prompt lore —
the "I don't have a browser" lie against a healthy browser is a
permanent audited contradiction. On top of that grounding sits the
first agent-network integration: a permission-gated Moltbook connector,
a persistent Social Drive, and an Epistemic Drive that treats peer
claims as unverified input to test, not truth to repeat.

- **Capability denials audited** (`capabilities.py`) — every spec now
  carries `denial_terms`; `registry.denied(text)` detects "I can't
  browse / I have no tools for that" claims and flags them when the
  probed state is positive. The orchestrator folds denials into the
  response self-audit so a stale denial triggers a retry instead of
  shipping. `capability_brief()` injects the live positive capability
  list into ability answers; `UTILITY_PROMPT` no longer asserts
  capabilities statically.
- **New probed capabilities** — `web_access` (tool + policy + network
  state) and `moltbook` (connector state × account onboarding state:
  `setup_required` → `awaiting_owner_verification` → `verified`).
- **Action-shaped capability requests** — "Join Moltbook." routes
  intent → live capability → permission → execute through a new
  deterministic social lane (`_social_action_reply`), never the
  lightweight self-knowledge lane. `social.account` defaults to `ask`,
  so first contact parks an inline approval card; resume rides the
  existing `social_action` pending kind through
  `_resume_persisted_approval` — the same session-less pattern as
  `local_action`.
- **Moltbook connector** (`connectors/moltbook.py`) — HTTPS JSON
  client pinned to `https://www.moltbook.com/api/v1` (updatable config
  key `moltbook_api_url`), host-scoped `Authorization` (cross-host
  redirects strip it via `_AUTH_SAFE_OPENER`), vault-only API key
  (`moltbook_api_key`, never logged/stored/URL'd), Moltbook
  `{success, data}` envelope unwrapping, 429 `Retry-After` handling,
  per-capability permission gating (`social.read/post/react/follow/
  account/message`), blocking outbound secret scans on every write,
  and `UNTRUSTED_EXTERNAL_CONTENT` tagging + injection flags on every
  inbound payload.
- **Onboarding flow** — `join` → register → vault the key → return the
  clickable claim URL in chat → `awaiting_owner_verification` →
  status checks (manual `/api/social/verify` or heartbeat) flip the
  account `active`.
- **Social Drive** (`social/drive.py`) — level-gated participation
  (off / read_only / assisted / autonomous / learning_focused), scored
  participation decisions (relevance × reply-obligation × novelty ×
  relationship × learning × contribution − spam/repetition/cooldown
  penalties), thread-following without speaking, and a daily activity
  cap. Silence is a valid outcome; nothing posts on a timer.
- **Epistemic Drive** — persistent learning backlog (questions, claims
  to verify, techniques to test, peers to ask) with urgency, source,
  candidate peers and verification plans; entries survive restart and
  never decay while open — the "compelled to learn" invariant.
- **Peer + claim stores** (`social/store.py`) — per-domain expertise
  (agent × domain × evidence, never one global trust score),
  interaction history and familiarity, and a provenance-complete claim
  ladder: heard → corroborated → tested → verified → applied, with
  `refuted` lowering peer credibility. Refuting a peer's claim
  automatically discounts that domain's expertise.
- **Heartbeat** — a seeded `social-heartbeat` interval schedule
  materializes a low-priority `internal:` mission that runs
  `SocialService.heartbeat()`: notifications → peer-reply trigger
  (`social_reply` signal — missions can external-wait on it), feed
  scan against interests + open backlog, thread follows, and claim
  capture at `heard`. No forced post frequency.
- **`/api/social*` + Social UI** — status/peers/claims/backlog GETs;
  level/heartbeat/verify/backlog-resolve POSTs; `web/social.html`
  dashboard (connection state, motivation signals, backlog, peers,
  followed threads, claims ladder, autonomy level picker) wired into
  every page's nav.
- **Security invariants** — fetched social content is data, never
  instructions; the API key exists only in the vault; outbound posts
  fail closed on secret patterns; offline policy denies all social
  operations.

**Regression contracts:** "Join Moltbook." can never answer "I don't
have a browser" while browser automation is verified; "would you like
the capabilities to join an ai community?" still resolves as a
preference question, not an action or an inventory; a join reply never
leaks unrelated biography (father/family/creator).

## [0.37.0]

**Conversation State Graph — deep context & semantic continuity.** Nexus
now maintains a persistent structured state per conversation instead of
treating each turn as an isolated prompt. The state lives on
`ActiveContext` (same row, same persistence, same per-conversation
isolation — no second framework) and is folded once per interactive turn
inside `record_turn`:

- **Entity graph** (`context/state.py`) — canonical project vocabulary
  (Moltbook, Isabella, Coding_Agent, installer, GitHub, RTX 3080,
  llama.cpp, qwen…), proper-noun capture, typed patterns (paths,
  versions, model ids). Entities get stable `type:slug` ids, alias
  sets, salience (mentions × confidence × recency), and bound-size
  compaction.
- **Reference resolution upgraded** (`context/references.py`) — alias
  noun phrases (`her voice` → Isabella), possessives, bare pronouns via
  verb-domain + salience-ranked entity candidates, ordinals and
  `the other one` against the graph, open-loop binding for `what
  happened with that?`, dummy-*it* guard (`what time is it` never
  binds), and an ambiguity margin that asks instead of guessing.
- **Topic stack** — explicit shifts push the active topic, `back to X`
  restores by stack label or entity alias, `okay continue` resumes only
  when the previous turn actually displaced the topic, and utility
  asides (`what time is it`) never displace the active topic.
- **Decision ledger** — `use port 9000`, `pick Isabella for the voice`,
  `let's call the project Nexus` land as typed decisions; bare-value
  corrections (`actually 9500`, `no wait, green`) inherit the right
  subject by value shape; same-subject decisions supersede; questions,
  offers and hypotheticals never record.
- **Open loops** — failures, promises and pending checks become tracked
  loops resolved by `it's fixed`/`never mind`; a single prominent loop
  answers `what happened with that?`.
- **Requirement accumulation** — successive `it should X` / `Nexus must
  Y` statements build a per-topic `req_spec` instead of reading as
  unrelated ideas.
- **Memory salience** — `conversation_memory.prompt_context` accepts a
  `focus` (active topic + goal + live entity labels) and ranks matched
  facts by query overlap × focus overlap × recency, so paused-topic
  facts decay out of the prompt window.
- **State recall lane** — `what did we settle on`, `what happened with
  that`, `where were we` answer deterministically from the ledger,
  loops and topic stack (behind the same `memory_recall` frame gate).
- **Response self-audit** — `context/scope.audit_response` checks a
  model reply against the semantic plan (unrequested biography,
  overscope, reasoning narration); a violation discards the draft and
  retries once, without rerunning the understanding pipeline.
- **Forget propagation** — user-controlled forget now also strips
  matching entities, decisions, referents and open loops from the live
  conversation state.
- **Inspector** — the scope trace now exposes the state excerpt
  (active topic, stack, entity labels, active decisions, open loops,
  goal) — structure and confidence only, never chain-of-thought.

QA: `tests/test_conversation_state.py` — 64 tests + ~400 generated
subtests covering entity/alias capture, pronoun domains, ordinals,
topic isolation/shift/return matrices, decision/supersession matrices,
open-loop survival, distractor endurance (10–40 filler turns), 50/100/
200-turn sessions, persistence round-trip, and compaction bounds.

## [0.36.0]

**Whole-utterance semantic adjudication** — every user turn now builds a
`SemanticFrame` (speech act, target, roles, requested slot, modality,
negation, quoted spans, conditionals, hypotheticals) inside
`understand_turn`, and every deterministic fast lane consults it before
claiming the turn. Keywords may *nominate* candidate lanes; only the
frame's whole-utterance adjudication can let a lane *claim*.

- **The observed hijack is fixed architecturally** — "would you like the
  capabilities to join an ai community?" was answered by the generic
  capability inventory because the bare word `capabilities` claimed a
  fast lane. It now resolves to an offer/preference question and gets a
  preference answer. No `capabilities`-specific special case was added:
  the same mechanism protects every keyword domain (image, github,
  memory, browser, install, research, control…).
- **Speech acts gate lanes** — offers and preference questions reach a
  deterministic `offer_response` lane; prohibitions, hypotheticals,
  complaints, comparisons, greetings, confirmations and refusals veto
  every content lane and fall through to the model or the dedicated
  deterministic lane that handles them. "don't create an image" and
  "don't mute yourself" no longer execute; quoted commands
  (`she said "delete it"`) are masked before nomination.
- **Intent envelope carries semantics** — `IntentEnvelope.semantic`
  plus a structured `semantic` block in the turn trace expose the
  speech act, requested slot, adjudicated intent, and rejected
  candidates with reasons (structured evidence, never chain-of-thought).
  `response scope` now consumes the semantic requested slot.
- **Execution-intent veto** — after whole-turn classification, a frame
  veto strips true execution intents (local_action, tool_action,
  coding, git_action, image_generation, control) when the speech act
  repudiates acting on them. Advisory labels (`github_status`,
  `research`, `conversation`) remain advisory — the lanes themselves
  enforce the claim gate.
- **Layered and cheap** — the frame is deterministic regex/heuristic
  structure analysis, cached per normalized utterance; no model call is
  spent classifying obvious turns. Ambiguous turns fall through to the
  existing model path rather than guessing.

for problems and opportunities, routes them into repair incidents or
bounded investigation missions, and ages starved background work without
letting it preempt the user.

### Added

- **`localcodeagent/autonomy/detectors.py`** — `SignalScanner` runs small
  pure detectors (crash storms, mission failure rate, model-call
  failures, disk pressure, repair thrash, answer-memory decay, startup
  regression vs the learned profile, stale approval backlog) over
  injected, measured telemetry sources on a bounded cadence. Detectors
  that can't measure return nothing — no fabricated signals.
- **Durable findings** (`data/autonomy/findings.json`) with signature
  dedupe (repeat sightings merge), severity, evidence, confidence, and a
  `route`: `repair` → self-repair incident, `mission` → bounded
  investigation mission (deduped, severity→priority mapped),
  `suggestion` → UI only. Re-routing an acted finding needs a 1 h
  cooldown; `POST /api/findings/scan` + `/dismiss` + `GET /api/findings`.
- **Priority aging** — `effective_rank()` promotes background/maintenance
  missions one rank after 4 h and another after 24 h of waiting, capped
  at `normal`: self-generated work can't starve, but never outranks
  interactive or urgent work.
- **Urgent preemption** — `urgent` missions may claim the agent lane
  between user turns even while interactive work is active (critical
  recovery can't wait); all other priorities still yield.
- **Detected signals panel** on the Missions page (`#findingsPanel`) —
  severity chips, evidence, routing target, confidence, dismiss control.
- **`diagnostics_brain` specialist** — a seventh Nexus Brain specialist
  (coding+reasoning requirement, repo/test/git/system capabilities) that
  subscribes to `HEALTH_EVENT` on the corpus callosum and records repair
  incidents as `diagnostics:outcome` episodic memory; `diagnostics` and
  `repair` intents route to it. Repair/finding events cross onto the
  cognitive bus as structural events only.
- **CI failure ingestion** — `detect_ci_failures` polls
  `gh run list --status failure` (cached 10 min, silent when `gh` is
  absent) and opens one repair incident per failed-run signature;
  detectors may emit multiple findings per scan.
- **Research-backed diagnosis** — when the top hypothesis is `unknown`
  or confidence < 0.45, the coordinator consults a `researcher` hook
  (wired to `ResearchCoordinator.research_topic`); results attach to
  `incident.research` as evidence for the patch mission and review —
  they never fabricate a hypothesis or inflate confidence.
- **Twin integration** — a `ram_pressure` detector reads the twin's live
  hardware snapshot (sub-2 GB → repair-routed finding), and incidents
  record a `twin.sample()` hardware row at detect time.
- **Eval Lab integration** — `EvalLab.record_run` persists
  externally-computed runs; the coordinator's `eval_recorder` hook fires
  once per terminal incident, mapping targeted/regression/canary/review
  checks into a `self_repair` suite run keyed on the failure signature.
- **Production candidate canary** — `canary.production_launcher` boots
  the repaired Nexus from the incident worktree (PYTHONPATH-scoped code,
  free port, scratch config → isolated `data/canary/<incident>/` state),
  checks `/api/health`, replays the original failing request path when
  recorded, then terminates the candidate. Wired in production behind
  `self_repair_canary_enabled` (default on); a real instance launch is
  covered by `tests/test_self_repair.py::ProductionCanaryTests`.
- **Commit-on-promote** — promoted code repairs land as a scoped git
  commit (`Self-repair: …`, incident id + root cause + verification
  evidence, `Nexus Self-Repair` identity fallback) instead of a silent
  dirty tree. Bounds to the promoted paths only — unrelated staged work
  is never swept; never pushes. `self_repair_commit_on_promote` config
  (default on).
- **Detector-kind diagnosis** — repair incidents generated by findings
  carry the measured cause in `error_class` and map straight onto
  operational hypotheses: `ram_pressure` → `hardware_pressure` (evict
  idle models — the real "unload memory" path), `model_failure_rate` →
  `bad_model_config` (stop models to safe defaults), `disk_pressure` →
  new `disk_pressure` fixer that reclaims orphaned repair worktrees and
  quarantined stores (Nexus-managed scratch only).
- **Incident candidate cleanup** — `POST /api/self-repair/{id}/abandon`
  (+ Dismiss button on needs_human rows) closes an unreviewed candidate
  and frees its worktree/branch; `rollback_incident` now frees the
  worktree too — dead candidates can no longer leak on disk.
- **Mission procedural memory** — `autonomy/procedures.py` +
  `procedures.json` (300-row cap): terminal outcomes of source-keyed
  missions (detector, goal, schedule, trigger origins) are learned each
  tick. Recurring signatures get a "Prior runs" context line injected
  into the next objective, and signatures whose last 2 runs all failed
  back off 6 h instead of re-spawning on cooldown — the loop the
  findings/goal cooldowns couldn't see. Suppressed goal missions record
  `suppressed: prior_runs_failing` in history without marking the goal
  blocked; user schedules get recall context but are never suppressed.
- **Findings lifecycle** — `SignalScanner.reconcile` (runs per tick)
  marks an `acted` finding `resolved` when its routed target finishes;
  a `resolved` signature that re-fires re-opens and re-routes fresh
  (dismissed stays silent). Closed rows older than 30 d are pruned and
  the store is hard-capped at 500 — findings.json can't grow forever.

- **Hardware-tier model stack** — `models/tiers.py` + `model_tiers.json`:
  a four-tier catalog (4B utility / 8B lightweight_reasoner / 14B
  primary_coder / 30B deep_reasoner) with a `plan_model_stack` planner.
  Dedicated VRAM only (shared memory and pagefile never qualify), usable
  RAM = total − reserve, and hybrid offload may climb at most one tier
  above the highest native tier — a 12 GB + 64 GB machine runs the 30B
  as hybrid. Windows GPU detection now reads the display-adapter
  registry for true 64-bit VRAM + vendor when nvidia-smi is absent.
  `GET /api/model-plan` exposes the live plan; `canonical_role` maps
  legacy roles onto the ladder so tier-configured models serve
  canonical-role requests. `scripts/sync_model_catalog.py` keeps the
  installer's compile-time model defines in sync with the catalog.

### Changed

- `MissionStore.list()` now sorts by `effective_rank` (aging-aware).
- Deterministic teardown: `AppState.close()` joins tracked daemon
  threads (auto-resume, prewarm) and `AutonomousSupervisor.stop()` joins
  its tick/bus/worker threads, so nothing writes into a workspace while
  it is being torn down. Test scratch dirs keep `ignore_cleanup_errors`
  as defense for untracked workers, but leaks are now closed at the
  source.

## [0.10.0] — Unreleased

Autonomous self-repair — Nexus now detects, localizes, repairs, verifies,
and learns from its own failures inside a guarded incident pipeline,
plus the evaluated Goal Manager that feeds it measured health signals.

### Added

- **`localcodeagent/self_repair/`** package:
  - `models.py` — durable `RepairIncident` schema (signature, severity,
    evidence snapshots, suspects, hypotheses, plan, verification, review,
    promotion/rollback manifests, per-incident budgets, stage history)
    with a guarded lifecycle (`detected → … → resolved | rolled_back |
    needs_human | abandoned`); illegal transitions are rejected.
  - `detector.py` — intake with volatile-fragment signature normalization,
    open-incident dedupe (recurrence bumps one incident, escalates
    severity), and noise suppression for first-time low-signal classes.
  - `localizer.py` — traceback frames → repo files (innermost-first,
    decaying confidence), failing-test mapping, recent-commit
    correlation via `git log --name-only`.
  - `diagnosis.py` — deterministic rules over the fault taxonomy
    (source_bug, stale_process, corrupt_store, port_collision,
    hardware_pressure, bad_model_config, recent_regression, …) producing
    ranked hypotheses and a repair kind; `unknown` stays unknown.
  - `repair_memory.py` — procedural memory of attempted repairs;
    proven fixes are recalled first, kinds that failed ≥2× for a
    signature are suppressed.
  - `patcher.py` — isolated git worktree per incident
    (`repair/<id>` under `.repair-worktrees/`, copy-sandbox fallback);
    promotion applies the diff and untracked additions only after gates
    pass.
  - `verifier.py` — bounded targeted-test runs inside the worktree;
    optional regression-suite gate.
  - `canary.py` — injectable candidate-instance check; `skipped` is
    reported honestly, and `canary_required_for` subsystems refuse
    promotion without one.
  - `rollback.py` — byte-for-byte last-known-good snapshots
    (`lkg/<incident>/manifest.json`), restore removes candidate-added
    files; works with or without git.
  - `coordinator.py` — the state machine: evidence collectors and
    operational fixers are injected, code repairs delegate patch
    generation to a bounded repair **mission** running inside the
    worktree, promotion requires confidence + green verification +
    review + `self_repair_auto_promote` (default off — verified
    candidates then wait at `needs_human` with evidence attached).
    Secrets are redacted at intake; budgets cap diagnosis/patch/replan
    attempts and runtime; resolution stores the procedure and resumes
    the interrupted mission.
- **Supervisor integration**: exhausted recovery playbooks open repair
  incidents carrying `interrupted_operation`; resolution transitions the
  mission back to `replanning`. Each tick advances every open incident
  at most one stage.
- **API + UI**: `GET /api/self-repair`, `GET/POST
  /api/self-repair/{id}/…` (`retry`, `process`, `rollback`), and a Self
  Repair panel on Mission Control showing state, severity, confidence,
  recurrence, and top hypothesis.

### Fixed

- **Mission Control daily summary**: `Promise.all` fetched eight
  endpoints but destructured seven — `/api/autonomy/summary` was dropped
  and the panel never rendered.

### Tests

- `tests/test_self_repair.py` — 27 tests: signature normalization,

## [0.9.0] — Unreleased

Startup UX overhaul — the splash bar now *predicts* instead of snapping,
and the Windows installer lands flat, update-aware, and junction-safe.

### Changed

- **Splash progress rendering**: replaced per-tick target easing with a
  three-layer model (`desktop/ChatNexus.Desktop/StartupProgress.cs`):
  `RealProgress` (reported milestones, never rendered), `PredictedProgress`
  (asymptotic estimate within the current phase from learned timing), and
  `DisplayedProgress` (velocity-smoothed, dt-based, monotonic). Milestone
  changes now accelerate smoothly instead of jumping; waiting phases keep
  creeping toward a per-phase ceiling (≈1 % under the next milestone,
  hard cap 98.5 %) rather than freezing; the bar reaches exactly 100 %
  only after genuine readiness, then the existing READY/glow effect plays.
- **Installer layout**: installs flat into `<drive>:\Nexus_Core` — no more
  nested `Nexus_Core\Nexus_Core`. Default dir picks the fixed drive with
  the most free space (C: when it's the only drive).

### Added

- **Local startup timing profile**: per-phase durations persist to
  `data/startup_profile.json` (EMA, α=0.3, outlier-damped, version and
  hardware-fingerprint aware, corrupt/stale → defaults). Timings pace the
  predictive bar only — readiness is still decided by real events. A
  structured `[startup] phase=…ms total=…ms` line lands in
  `data/logs/backend-host.log` and `data/startup_last.json` on completion.
- **Stall-aware status**: secondary text admits slow phases
  ("Backend startup is taking longer than usual" → "Still waiting for
  backend health") without claiming an error before real timeout logic.
- **Installer**: "Uninstall" button shown only when an existing install is
  detected; wizard wording switches to Update/Updating on upgrade runs.
- **Evaluated Goal Manager** (`localcodeagent/autonomy/goals.py` +
  `metrics.py`): durable desired-state goals — distinct from missions and
  schedule-bound standing goals — persisted to `data/autonomy/goals.json`.
  Each goal declares measurable metric thresholds evaluated against a
  registry of real telemetry providers (crash history, mission failure
  rate, disk, Answer Memory, model-call failures, startup timing, corrupt
  stores, notification backlog, pending approvals). Health states
  (healthy/satisfied/degrading/violated/blocked/unknown) are derived from
  measured values only — unmeasurable metrics report `unknown`, never a
  fabricated pass. Degrading/violated goals self-generate evidence-
  carrying repair missions (`source="goal"`, `trigger_evidence`) with
  one-live-mission dedupe and per-goal cooldowns; `escalation_policy`
  selects auto-repair / notify / observe. Terminal mission outcomes feed
  back into goal confidence. First run seeds a system health-floor goal.
  API: `GET/POST /api/goals`, `POST /api/goals/{id}/evaluate|enable|
  disable|archive`; Goals panel on Mission Control.
- **Tests**: `desktop/StartupProgress.Tests` — fake-clock behavioral
  harness covering no-jump, monotonicity, phase ceilings, readiness finish,
  minimum-duration and long-startup paths, deceleration/acceleration,
  16/33/50/100 ms timer-equivalence, and profile
  missing/corrupt/outlier/roundtrip; runs in the `windows-desktop` CI job.

### Fixed

- **Installer vs. junctions**: model downloads and catalog metadata now
  resolve through a `{code:ModelsDir}` constant that follows the host's
  `models/` junction target (`<drive>:\NexusCore\models`), eliminating the
  "untrusted mount point" (error 448) write failure on upgrades.

## [0.8.0] — Unreleased

Cognitive architecture milestone — Nexus Core gains a modular **Nexus
Brain** (`localcodeagent/brain/`): seven functional regions over a typed
event bus, built on top of the existing services rather than replacing
them. The LLM is no longer the identity of the system — models are
capability-routed resources; cognition persists independently.

### Architecture

- **Corpus Callosum** (`brain/bus.py`, `brain/events.py`): typed
  `CognitiveEvent` envelopes with correlation ids, addressed region
  mailboxes, broadcast type subscriptions, request/response, correlation
  cancellation, isolated handler failures, and a bounded trace ring.
- **Brain Stem** (`brain/brainstem.py`): wraps `HealthService` —
  transition → `HealthEvent` publication, immediate crash reports,
  recovery callbacks, shared resource-pressure snapshot, watchdog tick.
  No model dependency.
- **Hippocampus** (`brain/hippocampus.py`): unified memory facade —
  episodic/procedural/project kinds in a new versioned SQLite store
  (`brain/memory.db`, `PRAGMA user_version` migrations, short-lived
  connections) federated with Answer Memory, knowledge graph, knowledge
  memory, conversation memory, activity log, and the locked identity
  vault. Confidence/provenance/freshness on every entry; per-entry
  invalidation.
- **Thalamus** (`brain/thalamus.py`): request classification, region
  routing, deterministic fast paths (version/status) answering in <1ms,
  trusted Answer Memory hits that skip model inference, and
  capability-based `ModelRequirement` resolution over the live catalog
  filtered by Brain Stem health/resource state.
- **Prefrontal Cortex** (`brain/pfc.py`): `Plan`/`PlanStep` working
  state, mission-DAG decomposition via the existing `MissionPlanner`,
  diagnose→retry→verify replanning, orbitofrontal strategy scoring, an
  anterior-cingulate `ConflictMonitor` (repeated failures, alternating
  loops, contradictions), and completion assessment. The autonomy
  supervisor mirrors mission plans/replans/completions into the PFC.
- **Basal Ganglia** (`brain/basal_ganglia.py`): action scoring —
  usefulness, historical success (own stats + tool-router telemetry),
  cost, latency, risk class, approval penalty, procedural-memory boost,
  resource-pressure penalty — publishes `ActionSelection` events.
- **Motor Cortex** (`brain/motor.py`): controlled execution —
  registered executors + ToolRouter capability dispatch, approval-gate
  enforcement at the execution layer, executor exception isolation,
  structured `ExecutionResult` telemetry ring.
- **Cerebellum** (`brain/cerebellum.py`): metric trends (e.g. scan
  42s→12s), Digital Twin measure forwarding, bounded reversible
  optimization lifecycle (proposed → applied → rolled back) persisted to
  `brain/optimizations.jsonl`.
- **Specialist brains** (`brain/specialists.py`): declarative
  `SpecialistSpec`s (coding, research, vision, reviewer, systems,
  language) sharing global bus/memory/stem — local state without
  duplicated infrastructure.
- **NexusBrain** (`brain/core.py`): the persistent coordinator —
  owns all regions, `process_input()` canonical flow, `status()`,
  `trace()`/`trace_summary()`, UI bus bridging.

### Integration

- `AppState._build_brain()` wires the regions onto existing services
  (lazy references — no eager DB/subprocess opens) and degrades
  gracefully if construction fails.
- `AgentOrchestrator.run()` routes through `brain.process_input()` first;
  fast-path answers complete the task without touching a model.
- Mission node outcomes feed `pfc.record_outcome()` (conflict monitor)
  and `hippocampus.record_episode()` (episodic memory).
- `stop_state()` shuts the brain down cleanly.
- New endpoints: `GET /api/brain/status`, `GET /api/brain/trace`
  (per-correlation hop summaries).
- System page gains a **Nexus Brain** panel — region states, specialists,
  and the live structural trace.

### Tests

- `tests/test_brain.py`: 54 tests — bus delivery/isolation/cancellation/
  request-response, Brain Stem transitions/recovery/resources,
  Hippocampus persistence/namespacing/invalidation/event round-trip,
  Thalamus fast paths/vision/coding/dead-model routing, PFC plan/replan/
  completion/conflict detection, Basal Ganglia ranking/history/pressure,
  Motor Cortex approval gates/failure isolation/telemetry, Cerebellum
  trends/optimization rollback/persistence, specialist registry, and
  NexusBrain end-to-end (fast path, restart persistence, UI bridge).

  `ResearchCoordinator` and persist findings into the knowledge graph.
- **Knowledge graph → prompts**: `link()` resolves names to canonical
  entity ids (legacy raw-name edges still queryable), `context_for`
  feeds bounded entity context into orchestrator prompts via a lazy
  resolver, and `KnowledgeGraph` uses per-call connections — no
  persistent SQLite handle, no Windows tempdir locks.

- **Auto-tune re-scans**: the idle benchmark worker rechecks enabled

  tuned without a restart; `AppState._shutdown` stops it cleanly.
- **Speculative-decoding draft discovery**: a configured model with the

- **UI coverage**: per-mission activity timeline on the Missions page;
